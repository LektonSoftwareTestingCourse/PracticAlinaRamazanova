### Объяснение полученного распределения

Большая часть тест-кейсов относится к уровням API и integration, тк проверяется работа Card Management и Authorization, обработка HTTP-запросов, взаимодействие сервисов, работа с базой данных, проверка владельцев карт, лимитов и баланса. Новые тест-кейсы тоже проверяют взаимодействие через RabbitMQ, работу outbox и доставку событий

Риска ice-cream cone нет: сквозных тестов всего 2 из 83 (2,4%), поэтому нет перекоса в большое количество E2E-проверок

При этом очень мало unit-тестов: их всего 3 (3,6%). В первую очередь можно увеличить число изолированных проверок бизнес-логики, например валидации PAN, расчёта лимитов и проверки баланса

Распределение не совпадает с ориентиром 70/20/10, это из-за того, что мы выбрали сценарии с большим количеством проверок взаимодействия компонентов. Пока важнее покрыть критичные интеграции, а потом уже постепенно увеличивать долю unit-тестов
