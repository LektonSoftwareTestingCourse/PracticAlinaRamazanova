# Тестовый план СМП

## 1. Область тестирования и подход

Тестируется вся СМП. Глубокая проверка выполняется для Authorization и Card-Management; остальные сервисы проверяются через smoke, API, интеграционные и E2E-сценарии.

| Слой | Сервисы | Основные проверки |
|---|---|---|
| P1 | Authorization, Card Management | классы, границы, pairwise, unit, API |
| P1 | Switch, Transaction Logger | маршрутизация, RabbitMQ, логирование, идемпотентность |
| P2 | Gateway, Bin Lookup, Notification Service | API, fallback, ограничения, события |
| P3 | Terminal/Merchant Simulator, Dashboard | smoke и критический путь |

## 2. Критерии входа

- ТЗ и API-контракты доступны.
- `docker compose up -d` запускает систему.
- Все обязательные контейнеры healthy.
- `scripts/smoke-test.sh` проходит.
- Тестовые карты созданы.
- `test-design.md` и PICT-файлы готовы.

## 3. Критерии выхода

- Выполнено 100% P1-кейсов.
- Выполнено не менее 95% запланированных кейсов.
- Нет открытых Critical/High дефектов.
- Все основные decline-коды проверены.
- PICT покрывает 100% допустимых пар.
- Unit coverage бизнес-логики: ≥70% строк и ≥60% ветвлений.
- CI зелёный.
- Нагрузочный smoke: 500+ транзакций, неожиданные ошибки ≤1%.
- Открытые вопросы ТЗ, влияющие на P1, закрыты или имеют принятое допущение.

## 4. Критерии приостановки и возобновления

**Приостановить**, если не проходит smoke, недоступны обязательные сервисы, окружение нестабильно, найден блокирующий дефект или ТЗ/API изменились.

**Возобновить**, когда окружение исправлено, блокирующий дефект проверен повторно, а тесты синхронизированы с ТЗ.

## 5. Ресурсы

- Исполнитель: тестировщик.
- Окружение: Docker, PostgreSQL, RabbitMQ.
- Инструменты: Git/GitHub Actions, JUnit 5, Mockito, Testcontainers, PICT, REST-клиент.
- Данные: синтетические тестовые карты.

## 6. Расписание

| Этап | Содержание |
|---|---|
| 1 | Smoke и запуск СМП |
| 2 | Тест-дизайн: стратегия, план, классы, границы, pairwise |
| 3 | Unit-тесты |
| 4 | API и интеграционные тесты |
| 5 | E2E и дефекты |
| 6 | CI/CD и нагрузочный smoke |
| 7 | Метрики и отчётность |
| 8 | Финальная стратегия и защита |

## 7. Риски

| Риск | Мера |
|---|---|
| Неполное/противоречивое ТЗ | фиксировать допущения и вопросы |
| Нестабильное окружение | smoke перед прогоном |
| Много кейсов | сначала P1 |
| Flaky E2E | независимые данные и ограниченный набор |
| RabbitMQ работает асинхронно | использовать ожидание с таймаутом |

## 8. Метрики

- выполнено / пройдено / заблокировано;
- дефекты по severity и статусу;
- покрытие строк и ветвлений;
- покрытие пар PICT;
- покрытие API и decline-кодов;
- стабильность CI;
- p50/p95/p99 и error rate для нагрузочного smoke.
